# Auto Bidding System

Система автоматического управления ставками в рекламных RTB-аукционах.
Она помогает рекламодателю получать больше конверсий в пределах дневного бюджета
и распределять расходы в течение дня.

В основе решения — **UCB (Upper Confidence Bound)**: алгоритм сравнивает несколько
уровней ставки и выбирает между уже результативными вариантами и теми, о которых
пока мало данных. При необходимости решение дополняется моделью вероятности
конверсии, чтобы учитывать контекст конкретного показа.

## Статус проекта

Проект находится на этапе проектирования MVP. Описаны бизнес-требования,
алгоритм выбора ставок, архитектура и порядок оценки. Настроено окружение
разработки. Реализация стратегии, симулятора и прогнозной модели — следующие этапы.
Результаты экспериментов пока отсутствуют.

[Дизайн-документ](docs/ml_system_design_doc.md) содержит постановку задачи,
схемы бейзлайна и основного решения, план пилота и ограничения данных.

## Подход

- **Бейзлайн:** фиксированная ставка с контролем дневного бюджета и темпа расходов.
- **Основное решение:** UCB выбирает множитель базовой ставки отдельно для кампании.
- **Возможное расширение:** модель прогнозирует вероятность конверсии и помогает
  рассчитать базовую ставку для каждого показа; UCB продолжает выбирать множитель.
- **Оценка:** число уникальных конверсий, CPA, расходы и соблюдение бюджета
  при одинаковых условиях для всех стратегий.

## Данные

Используется [Criteo Attribution Modeling for Bidding Dataset](https://huggingface.co/datasets/criteo/criteo-attribution-dataset).
Он содержит контекст состоявшихся показов, кампании и последующие события,
в том числе конверсии, а также преобразованные стоимости. Лицензия набора —
**CC BY-NC-SA 4.0**; при использовании необходимо соблюдать её условия,
указывать авторство и цитировать статью авторов. Использование данных в текущем
проекте некоммерческое; коммерческое применение потребует другого источника
или соответствующих прав.

Бюджет и CPA в экспериментах измеряются в условных единицах датасета.
Отсутствие проигранных аукционов ограничивает оценку новой стратегии.
Симулятор позволит сравнить подходы на наблюдавшихся показах;
для подтверждения эффекта в реальных торгах потребуется отдельный пилот.

## Окружение разработки

Окружение управляется через [uv](https://docs.astral.sh/uv/getting-started/installation/).
Требуется Git и доступ к интернету для первой установки инструментов.
Для разработки используется Python **3.12**, указанный в `.python-version`;
проект сохраняет совместимость с Python 3.11 и новее. Из корня репозитория:

```bash
uv sync --locked
uv run pre-commit install
```

Uv создаёт локальную `.venv` и устанавливает зависимости, включая группу `dev`,
из `uv.lock`. При необходимости скачивает Python. Активировать окружение вручную
не нужно: команды запускаются через `uv run`. Проект пока не устанавливается
как Python-пакет.

Зависимости добавляются через `uv add`, инструменты разработки — через
`uv add --dev`. Изменения `pyproject.toml` и `uv.lock` сохраняются в Git вместе;
локальная `.venv` в репозиторий не попадает.

## Проверки качества

```bash
uv run ruff check .
uv run ruff format --check .
uv run pre-commit run --all-files
```

Для автоматического исправления Python-кода: `uv run ruff check --fix .`
и `uv run ruff format .`.
Pre-commit также проверяет YAML, TOML, конфликты слияния, размер добавляемых файлов,
лишние пробелы и окончания файлов. Версии Ruff в зависимостях и hooks совпадают.

Пока Python-кода нет, соответствующие проверки могут быть пропущены.
Новые файлы перед запуском `uv run pre-commit run --all-files` нужно добавить через
`git add`. Если hooks исправили файлы, изменения следует проверить и добавить
повторно. Данные, модели, результаты локальных экспериментов и секреты в Git
не хранятся.
